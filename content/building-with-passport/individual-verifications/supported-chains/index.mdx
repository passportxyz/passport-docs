# Supported Chains

Individual Verifications issue attestations on multiple blockchain networks, allowing users to verify once and prove their identity across different ecosystems.

## Overview

Each chain has one of two roles. A payment chain is where the user pays the verification fee. A delivery chain is where the user receives the proof: a Sign Protocol attestation on Optimism, or a soulbound token (SBT) on Stellar and Sui. The two can differ. A user can pay on Base and receive the proof on Optimism, Stellar or Sui.

| Chain | Payment | Delivery | Gov ID | Phone | Biometrics | Clean Hands |
|-------|---------|----------|--------|-------|------------|-------------|
| **Optimism** | ✅ | Sign Protocol attestation | ✅ | ✅ | ✅ | ✅ |
| **Ethereum** | ✅ | - | - | - | - | - |
| **Base** | ✅ | - | - | - | - | - |
| **Avalanche** | ✅ | - | - | - | - | - |
| **Stellar** | - | SBT | ✅ | ✅ | - | - |
| **Sui** | - | SBT | - | - | - | ✅ |

Payment is in the native coin of the payment chain: ETH on Ethereum, Optimism and Base, and AVAX on Avalanche. Stellar and Sui take no payment.

## How Multi-Chain Verification Works

1. **Single Verification**: User completes identity verification once (KYC, phone, biometrics, etc.)
2. **Chain Selection**: User chooses which blockchain to receive their proof
3. **Proof Issuance**: A Sign Protocol attestation is issued on Optimism, or an SBT is minted on Stellar or Sui
4. **Cross-dApp Usage**: The proof can be verified by any application on that chain

<Callout type="tip">
For enhanced privacy, users can pay verification fees from a different wallet than the one receiving the attestation. This prevents timing correlation attacks.
</Callout>

## Optimism

Optimism is the primary chain for Individual Verifications, with full support for all verification types. Optimism is also a payment chain.

**Supported Verifications:**
- Government ID (KYC)
- Phone
- Biometrics
- Proof of Clean Hands

### Sign Protocol Configuration (Optimism)

| Component | Value |
|-----------|-------|
| Schema ID (Gov ID, Phone) | `onchain_evm_10_0x1` |
| Schema ID (Biometrics, Clean Hands) | `onchain_evm_10_0x8` |
| Attester | `0xB1f50c6C34C72346b1229e5C80587D0D659556Fd` |
| Chain ID | 10 |

### Querying Attestations on Optimism

```bash
curl 'https://mainnet-rpc.sign.global/api/index/attestations?schemaId=onchain_evm_10_0x1&attester=0xB1f50c6C34C72346b1229e5C80587D0D659556Fd'
```

Use `schemaId=onchain_evm_10_0x8` for Biometrics and Proof of Clean Hands.

For complete query examples and validation code, see [Attestation Protocols](/building-with-passport/individual-verifications/major-concepts/attestation-protocols).

## Base

Base is a payment chain only. Users pay the verification fee on Base and receive the proof on Optimism, Stellar or Sui.

---

## Stellar

Individual Verifications support Stellar via Soroban smart contracts for Government ID and Phone verifications. Stellar takes no payment. The user pays on an EVM chain and enters a Stellar address to receive the SBT.

**Supported Verifications:**
- Government ID (KYC)
- Phone

### SBT Contract

| Component | Value |
|-----------|-------|
| SBT Contract | `CCNTHEVSWNDOQAMXXHFOLQIXWUINUPTJIM6AXFSKODNVXWA4N7XV3AI5` |

<Callout type="info">
On Optimism, attestations via Sign Protocol are the recommended integration. On Stellar and Sui, SBTs are the current method. See the [Stellar Integration](/building-with-passport/individual-verifications/supported-chains/stellar) page for complete code examples and integration details.
</Callout>

### User Flow

1. Visit the verification page for the desired verification type
2. Complete the verification process
3. Enter a Stellar address to receive the verification
4. The verification is recorded on Stellar as an SBT

---

## Sui

Sui supports Proof of Clean Hands. The proof is delivered as an SBT. Sui takes no payment. The user pays on an EVM chain and enters a Sui address to receive the SBT.

**Supported Verifications:**
- Proof of Clean Hands

### SBT Package

| Component | Value |
|-----------|-------|
| Package ID | `0x53ddebd997f0e57dc899d598f12001930e228dddadf268a41d4c9a7c1df47a97` |
| SBT type | `0x53ddebd997f0e57dc899d598f12001930e228dddadf268a41d4c9a7c1df47a97::sbt::SoulBoundToken` |
| Network | Sui Mainnet |

Source code: [GitHub](https://github.com/holonym-foundation/id-hub-contracts/blob/main/contracts/sui/human-id/sources/sbt.move)

To check whether an address holds an SBT, list the objects the address owns and filter by the SBT type.

### User Flow

1. Complete Proof of Clean Hands verification
2. Select Sui as the chain and enter a Sui address
3. The SBT is minted to that address on Sui

## Sandbox / Testnet

For testing and development, use Optimism Sepolia testnet.

### Sign Protocol Configuration (Sandbox)

| Component | Value |
|-----------|-------|
| Schema ID | `onchain_evm_11155420_0xc41` |
| API Endpoint | `https://testnet-rpc.sign.global/api/index/attestations` |
| Chain ID | 11155420 (Optimism Sepolia) |

### Sandbox Verification URLs

| Verification | Sandbox URL |
|--------------|-------------|
| Government ID | `https://id.human.tech/gov-id?sandbox=true` |
| Phone | `https://id.human.tech/phone?sandbox=true` |
